The C Writing Ladder

Eighteen programs that start at "type the skeleton from memory" and end at the shape of a real assignment. Each one has an exact expected output, so you never have to wonder whether you got it right.

How to work through this

  1. Open PowerShell in the problems folder: cd "D:\shopify AI toolkit\c-course\problems"
  2. Write your program in a file named after the problem — p01.c, p02.c, and so on. Type it out; do not copy from anywhere. Only ever create .c files here; the .in and .out files are the checker's, and overwriting one breaks it.
  3. Run .\check.ps1 p01. It compiles, runs, and compares your output against the expected output line by line — printing PASS or showing you exactly which line differs and how. (On Git Bash or WSL, use bash check.sh p01 instead.)
  4. Only open a Hint after you have tried and failed. Only open a Solution after you have passed, to compare — or after a hint didn't rescue you.

PowerShell note: Windows PowerShell 5.1 does not understand && for chaining commands. Use ; instead, or just run the two commands on separate lines.

The rule that makes this work: your output must match exactly — every space, every colon, every decimal place. That feels pedantic and it is the point. Getting printf to produce a precise shape is half of what an assignment is actually graded on.

TIER 1

Skeleton and printf

The goal here is not thinking, it is muscle memory. You should be able to produce a compiling C file from an empty editor without pausing. Type the #include, the main, the return 0; every single time — never copy the previous file.

p01

Three lines

Print exactly three lines of text. Nothing clever — this problem exists so that you type the program skeleton from a blank file.

Expected output

Hello, world!
This is my first C program.
It prints three lines.
Hint

Four things every C file needs: #include <stdio.h>, then int main(void) {, then your work, then return 0; and a closing brace.

Each printf needs \n at the end or the lines will run together.

Solution
#include <stdio.h>
int main(void) {
    printf("Hello, world!\n");
    printf("This is my first C program.\n");
    printf("It prints three lines.\n");
    return 0;
}
p02

One of each type

Declare four variables — an int holding 20, a float holding 1.78, a double holding pi to 14 places, and a char holding the letter A — then print each with the correct format specifier.

Expected output

age    = 20
height = 1.780000
pi     = 3.14159
grade  = A
Hint

The specifiers you need are %d, %f, %.5f and %c. Note that plain %f prints six decimal places by default — that is why height shows as 1.780000 without you asking.

A char literal uses single quotes: 'A'. Double quotes would make it a string, which is a different thing entirely.

Solution
#include <stdio.h>
int main(void) {
    int    age    = 20;
    float  height = 1.78f;
    double pi     = 3.14159265358979;
    char   grade  = 'A';
    printf("age    = %d\n", age);
    printf("height = %f\n", height);
    printf("pi     = %.5f\n", pi);
    printf("grade  = %c\n", grade);
    return 0;
}
p03

A lined-up receipt

Print a two-column receipt where the item names are left-aligned in a 10-character field and the prices are right-aligned in an 8-character field with two decimals. Finish with a line showing a tax rate that includes a literal percent sign.

Expected output

ITEM          PRICE
Coffee         3.50
Sandwich       7.25
Tax rate: 8%
Hint

A number between % and the letter sets the field width: %8.2f means "at least 8 characters wide, 2 decimal places". A minus sign makes it left-aligned instead: %-10s.

To print a literal % you must write %%. A single % makes printf look for an argument that isn't there.

Solution
#include <stdio.h>
int main(void) {
    printf("%-10s %8s\n", "ITEM", "PRICE");
    printf("%-10s %8.2f\n", "Coffee", 3.5);
    printf("%-10s %8.2f\n", "Sandwich", 7.25);
    printf("Tax rate: %d%%\n", 8);
    return 0;
}
TIER 2

Arithmetic that has to be exactly right

Every problem here contains at least one place where integer division would silently give you the wrong answer. Values are hard-coded so that the only thing being tested is whether your arithmetic and your types are correct.

p04

Rectangle

With w = 7 and h = 3 hard-coded, print the width, height, area and perimeter. All four values line up because the labels are padded to the same length.

Expected output

width     = 7
height    = 3
area      = 21
perimeter = 20
Hint

Perimeter is 2 * (w + h). Leave out the parentheses and precedence gives you (2*w) + h = 17, which compiles perfectly and is wrong.

Solution
#include <stdio.h>
int main(void) {
    int w = 7, h = 3;
    printf("width     = %d\n", w);
    printf("height    = %d\n", h);
    printf("area      = %d\n", w * h);
    printf("perimeter = %d\n", 2 * (w + h));
    return 0;
}
p05

Celsius to Fahrenheit

Convert 37 °C using the formula F = C × 9/5 + 32. Print to one decimal place.

Expected output

37 C = 98.6 F
Hint

This is the classic trap. If you write c * 9 / 5, everything is an int: 37×9 = 333, then 333/5 = 66 (not 66.6), and you end up with 98.0.

Write 9.0 instead of 9. One floating-point operand is enough to make the whole expression floating-point.

Solution
#include <stdio.h>
int main(void) {
    int c = 37;
    double f = c * 9.0 / 5.0 + 32.0;
    printf("%d C = %.1f F\n", c, f);
    return 0;
}
p06

Average of three

Three int variables hold 7, 8 and 10. Print their sum as a whole number and their average to two decimal places.

Expected output

sum     = 25
average = 8.33
Hint

The sum genuinely is an integer, so %d is right there. The average is where you need care: (a+b+c) / 3 gives 8, because both sides are integers.

Divide by 3.0, not 3.

Solution
#include <stdio.h>
int main(void) {
    int a = 7, b = 8, c = 10;
    double avg = (a + b + c) / 3.0;
    printf("sum     = %d\n", a + b + c);
    printf("average = %.2f\n", avg);
    return 0;
}
p07

Discount

An item costs 249.99 and there is a 15% discount. Print the original price, the discount percentage, the amount saved, and the final price — money always to two decimals.

Expected output

original: 249.99
discount: 15%
saved:    37.50
you pay:  212.49
Hint

Keep the percentage as an int so you can print it with %d%%, but divide by 100.0 when you use it in the calculation.

Saved rounds to 37.50 for display while the stored value is 37.4985 — which is why "you pay" is 212.49 and not 212.50 minus something. Compute the final price from the full-precision value, not from the rounded one.

Solution
#include <stdio.h>
int main(void) {
    double price = 249.99;
    int percent = 15;
    double saved = price * percent / 100.0;
    double final = price - saved;
    printf("original: %.2f\n", price);
    printf("discount: %d%%\n", percent);
    printf("saved:    %.2f\n", saved);
    printf("you pay:  %.2f\n", final);
    return 0;
}
TIER 3

Division and remainder as tools

These read a value with scanf and take it apart using nothing but / and %. This pair is the most useful thing in the whole module — splitting a number into parts is the backbone of dozens of assignment problems. The check.sh script feeds the input in for you from the .in file.

p08

Seconds to clock time

Read a number of seconds and print it as hours, minutes and seconds. Minutes and seconds are zero-padded to two digits; hours are not padded.

Input (p08.in)

3725

Expected output

1:02:05
Hint

scanf("%d", &t); — the & is required and forgetting it is the most common beginner crash in C.

Hours are t / 3600. Minutes are the leftover seconds divided by 60: (t % 3600) / 60. Seconds are t % 60.

Zero-padding is %02d — width 2, padded with zeros instead of spaces.

Solution
#include <stdio.h>
int main(void) {
    int t;
    scanf("%d", &t);
    printf("%d:%02d:%02d\n", t / 3600, (t % 3600) / 60, t % 60);
    return 0;
}
p09

Making change

Read an amount in cents and break it into the fewest US coins: quarters (25), dimes (10), nickels (5) and pennies. Labels are padded so the numbers line up.

Input (p09.in)

287

Expected output

quarters: 11
dimes:    1
nickels:  0
pennies:  2
Hint

The pattern repeats: divide to get how many of this coin, then use %= to shrink the amount down to what is left over. Then move to the next coin.

This is exactly where cents %= 25; earns its keep — it means "replace cents with the remainder", which is the whole idea.

Solution
#include <stdio.h>
int main(void) {
    int cents;
    scanf("%d", &cents);
    int q = cents / 25;  cents %= 25;
    int d = cents / 10;  cents %= 10;
    int n = cents / 5;   cents %= 5;
    printf("quarters: %d\n", q);
    printf("dimes:    %d\n", d);
    printf("nickels:  %d\n", n);
    printf("pennies:  %d\n", cents);
    return 0;
}
p10

Reverse a three-digit number

Read a three-digit number, print its three digits separated by spaces, then print the number with its digits reversed.

Input (p10.in)

472

Expected output

digits:   4 7 2
reversed: 274
Hint

Last digit: n % 10. First digit: n / 100. The middle one needs both — divide away the last digit, then take the remainder: (n / 10) % 10.

To rebuild the number, multiply each digit by its new place value and add.

Solution
#include <stdio.h>
int main(void) {
    int n;
    scanf("%d", &n);
    int h = n / 100;
    int t = (n / 10) % 10;
    int o = n % 10;
    printf("digits:   %d %d %d\n", h, t, o);
    printf("reversed: %d\n", o * 100 + t * 10 + h);
    return 0;
}
p11

Sum of digits

Read a four-digit number and print the sum of its digits. 4821 gives 4+8+2+1 = 15.

Input (p11.in)

4821

Expected output

sum of digits: 15
Hint

Same tool as p10, one place further. The four digits are n % 10, (n/10) % 10, (n/100) % 10 and n / 1000.

Without loops you have to write all four out. That is fine — noticing how repetitive it is is the motivation for loops, which is probably your next module.

Solution
#include <stdio.h>
int main(void) {
    int n;
    scanf("%d", &n);
    int sum = n % 10 + (n / 10) % 10 + (n / 100) % 10 + (n / 1000) % 10;
    printf("sum of digits: %d\n", sum);
    return 0;
}
TIER 4

Traps and techniques

Four things that look like puzzles and are actually standard techniques. Every one of these turns up in exam questions because each demonstrates something about how C really behaves rather than how it looks.

p12

Swap two variables, twice

Start with a = 3 and b = 9. Print them, swap them using a third temporary variable and print again, then swap them back using only arithmetic — no third variable — and print a final time.

Expected output

before: a=3 b=9
temp:   a=9 b=3
no tmp: a=3 b=9
Hint

The temp swap is three lines: save a, overwrite a with b, overwrite b with the saved value. Doing it in two lines loses a value forever.

The arithmetic swap is a = a + b; b = a - b; a = a - b;. Trace it on paper before you believe it. It is a party trick rather than good practice — real code uses the temp — but it shows that assignment is a sequence of steps, not a simultaneous exchange.

Solution
#include <stdio.h>
int main(void) {
    int a = 3, b = 9;
    printf("before: a=%d b=%d\n", a, b);
    int tmp = a;  a = b;  b = tmp;
    printf("temp:   a=%d b=%d\n", a, b);
    a = a + b;  b = a - b;  a = a - b;
    printf("no tmp: a=%d b=%d\n", a, b);
    return 0;
}
p13

Rounding without a library

For each of 3.7, 3.2 and 8.5, print what it truncates to and what it rounds to — without using math.h.

Expected output

3.7 truncates to 3, rounds to 4
3.2 truncates to 3, rounds to 3
8.5 truncates to 8, rounds to 9
Hint

Truncating is just (int)x. Rounding is the old trick: (int)(x + 0.5). Adding a half pushes anything with a fractional part of .5 or more up into the next whole number before the truncation chops it.

Worth knowing: this only works for positive numbers. (int)(-2.3 + 0.5) is (int)(-1.8) = −1, which is not the rounded value. Negatives need a different approach.

Solution
#include <stdio.h>
int main(void) {
    double x = 3.7, y = 3.2, z = 8.5;
    printf("%.1f truncates to %d, rounds to %d\n", x, (int)x, (int)(x + 0.5));
    printf("%.1f truncates to %d, rounds to %d\n", y, (int)y, (int)(y + 0.5));
    printf("%.1f truncates to %d, rounds to %d\n", z, (int)z, (int)(z + 0.5));
    return 0;
}
p14

Round to two decimals for real

Take 3.14159265 and actually round the stored value to two decimal places — not just display it that way. Print the original, the rounded value at two places, and the rounded value at eight places to prove the digits are really gone.

Expected output

original: 3.14159265
2 places: 3.14
stored:   3.14000000
Hint

%.2f only changes what is displayed. The variable still holds all the digits. To change the value itself: multiply by 100, round to a whole number, then divide by 100.0.

Watch the last division — dividing by 100 instead of 100.0 puts you straight back into integer division and gives you 3.

Solution
#include <stdio.h>
int main(void) {
    double v = 3.14159265;
    double r = (int)(v * 100 + 0.5) / 100.0;
    printf("original: %.8f\n", v);
    printf("2 places: %.2f\n", r);
    printf("stored:   %.8f\n", r);
    return 0;
}
p15

Watch a value wrap around

Show integer overflow happening. Put 250 in an unsigned char and add 10. Put the maximum value in an unsigned int and add 1. Print before and after each time.

Expected output

unsigned char at 250: 250
after adding 10:      4
unsigned int at max:  4294967295
after adding 1:       0
Hint

An unsigned char holds 0–255. 250 + 10 = 260, which does not fit, so it wraps to 260 − 256 = 4. A car odometer rolling over.

Print unsigned values with %u, not %d. The maximum unsigned int is 4294967295 — write the literal with a u suffix.

This is well-defined behaviour for unsigned types. Signed overflow is undefined behaviour, which is why this problem uses unsigned.

Solution
#include <stdio.h>
int main(void) {
    unsigned char small = 250;
    printf("unsigned char at 250: %u\n", small);
    small += 10;
    printf("after adding 10:      %u\n", small);
    unsigned int big = 4294967295u;
    printf("unsigned int at max:  %u\n", big);
    big += 1;
    printf("after adding 1:       %u\n", big);
    return 0;
}
TIER 5

Assignment-shaped

These are the size and shape of a real first assignment: read several values, compute several results, print a formatted report. Nothing new is required — they simply combine everything above without holding your hand. If you can do these three cold, the assignment will not surprise you.

p16

Unit converter

Read three numbers on one line — kilometres, kilograms and degrees Celsius — and convert all three. Use 0.621371 miles per km, 2.20462 pounds per kg, and the usual Fahrenheit formula. Everything to two decimals.

Input (p16.in)

10 70 21.5

Expected output

10.00 km = 6.21 miles
70.00 kg = 154.32 lb
21.50 C  = 70.70 F
Hint

One scanf can read several values: scanf("%lf %lf %lf", &km, &kg, &c);

Note the specifier. Reading into a double needs %lf, while printing a double uses plain %f. Mixing those up is a classic mistake and the compiler will warn you about it.

Look closely at the expected output — there are two spaces after the C so the equals signs line up.

Solution
#include <stdio.h>
int main(void) {
    double km, kg, c;
    scanf("%lf %lf %lf", &km, &kg, &c);
    printf("%.2f km = %.2f miles\n", km, km * 0.621371);
    printf("%.2f kg = %.2f lb\n",    kg, kg * 2.20462);
    printf("%.2f C  = %.2f F\n",     c,  c * 9.0 / 5.0 + 32.0);
    return 0;
}
p17

Three years of compound interest

Read a principal amount and an annual interest rate as a percentage. Print the balance after each of three years, then the total interest earned. Each year's balance is the previous year's multiplied by the growth factor.

Input (p17.in)

1000 5

Expected output

principal: 1000.00 at 5.0%
year 1:    1050.00
year 2:    1102.50
year 3:    1157.62
interest:  157.62
Hint

Compute the growth factor once: m = 1.0 + rate / 100.0. Then each year is the last one times m. Without loops, write the three steps out.

Year 3 prints as 1157.62, not 1157.63. The exact value is 1157.625, and floating-point binary cannot hold that precisely — it stores a hair under, so it rounds down. This is not your bug; it is what real money code has to deal with, and it is why banks do not store money in doubles.

Solution
#include <stdio.h>
int main(void) {
    double p, rate;
    scanf("%lf %lf", &p, &rate);
    double m = 1.0 + rate / 100.0;
    double y1 = p * m;
    double y2 = y1 * m;
    double y3 = y2 * m;
    printf("principal: %.2f at %.1f%%\n", p, rate);
    printf("year 1:    %.2f\n", y1);
    printf("year 2:    %.2f\n", y2);
    printf("year 3:    %.2f\n", y3);
    printf("interest:  %.2f\n", y3 - p);
    return 0;
}
p18

How long was the meeting

Read four numbers — a start hour and minute, then an end hour and minute, on a 24-hour clock. Echo both times zero-padded, then print the gap in total minutes and again as hours and minutes. Assume the end is after the start on the same day.

Input (p18.in)

9 30 14 15

Expected output

start:    09:30
end:      14:15
minutes:  285
duration: 4h 45m
Hint

The move that makes this easy: convert both times into a single number — minutes since midnight — subtract, and only convert back at the end. Trying to subtract hours and minutes separately means borrowing, and it gets messy fast.

Everything else you have already done in p08. Note that duration pads the minutes but not the hours.

Solution
#include <stdio.h>
int main(void) {
    int h1, m1, h2, m2;
    scanf("%d %d %d %d", &h1, &m1, &h2, &m2);
    int start = h1 * 60 + m1;
    int end   = h2 * 60 + m2;
    int diff  = end - start;
    printf("start:    %02d:%02d\n", h1, m1);
    printf("end:      %02d:%02d\n", h2, m2);
    printf("minutes:  %d\n", diff);
    printf("duration: %dh %02dm\n", diff / 60, diff % 60);
    return 0;
}
Every expected output here was produced by compiling and running a reference solution with gcc 14.2.0, not written by hand. If check.sh says your output differs, the difference is real.
